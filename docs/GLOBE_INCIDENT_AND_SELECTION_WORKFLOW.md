# Globe, incident and operator-selection workflow

This note describes the implementation contract for the AEGIS world view and the local deterministic response created from committed map inputs. The README release record identifies the deployed build and its verification evidence.

## Incident truth classes

AEGIS does not treat every provider record as a live alarm.

- **Current observed** — red marker and restrained pulse. The record must be observed rather than simulated, its provider retrieval status must be live, its incident state must be active or monitoring, and its freshness band must be live or near-real-time.
- **Source context** — neutral gray marker. This includes cached snapshots, aging or archived reports, degraded retrievals and records whose freshness cannot be established. It remains available for context but does not pulse red.
- **Simulation** — amber marker. It is generated by the deterministic AEGIS scenario engine and never presented as a real incident.

Incidents use one clustered WebGL renderer rather than duplicate WebGL and DOM pings. Marker labels use the same truth classification and include the compact source identity (for example USGS, GDACS or NASA EONET). Clustering and collision-aware labels limit overlap in dense regions. “Current observed” describes the named provider's current record, not an AEGIS field observation or confirmation of ongoing damage. Selecting a current observed marker imports its source context, focuses the map and runs separately labelled simulated impact geometry around that location. Simulated damage is not a claim of observed real-world damage.

## Operator input to automatic response

The map tools are operational inputs:

1. **Origin** places or replaces the evacuation start point.
2. **Safe point** places or replaces the screened destination.
3. **Source** places or replaces the hazard source.
4. **Area** collects three or more vertices. The boundary is not committed until the operator presses **Complete**.
5. **Clear** removes the pointers and boundary, closes the generated response overlays and returns to the clean Monitor globe. The action remains reachable from both the automatic assessment card and the detailed evacuation panel after those panels cover the original map-input rail.

Committing an **Origin**, **Safe point** or **Source** marker, or pressing **Complete** for an Area, triggers a local deterministic recalculation. **Inspect** clicks and individual draft area vertices do not trigger it. A committed pointer outside the previous planning domain recenters the domain so the calculation follows the operator's input rather than retaining an unrelated location.

Completing an area calculates its centroid and makes that the active planning location. The prototype supports region dimensions from **120 m to 100 km**. A selection outside those limits uses a visibly labelled **center-based model-domain fallback**; the result is not bounded to the entire drawn region. Recentering does not import authoritative local assets: geometry, terrain, occupancy and capacity retain their imported or estimated provenance.

The visible workflow is:

```text
committed Origin / Safe point / Source / completed Area
  -> client-side deterministic scenario rebuild
  -> hazard and timeline layers
  -> exposure and access screening
  -> evacuation route and capacity calculation
  -> local deterministic decision brief
  -> response package ready
  -> operator opens the detailed evacuation response
```

The compact status card first reports **Recalculating selected region**, then **Response package ready**. It shows which inputs were operator-placed versus model defaults or a model-domain fallback, the selected area, exposure, affected structures, route count and coverage. These are planning estimates, not confirmed damage or guaranteed safe routes. **Open evacuation response** reveals the detailed staged routes and response panel; a zero-route result remains valid when no route passes the model's screening.

## Globe camera and interaction

- The idle globe uses a slightly pitched projection and automatic rotation.
- Camera padding scales with viewport height so the sphere remains visually centered above the timeline rather than dropping low on tall laptop windows.
- Pointer, wheel and keyboard interaction pause the orbit temporarily; it resumes after the idle delay while the view remains at globe zoom.
- Regional and street searches hand off to Mercator projection before close zoom, retaining road, city, building and label context without forcing the spherical renderer into unsupported detail levels.
- Incident marker cores, glow and pulse rings use restrained sizes in the single clustered renderer. User-placed origin, safe-point, source and area markers remain visually distinct from passive global incident context.

## Safety boundary

The automatic output is a dry-run planning package. This map-input workflow does not send phone notifications, public alerts, government messages, SMS, siren commands or field dispatches. Exposure, damage, road status and evacuation outcomes are simulated or estimated unless an individual field is explicitly backed by a named observed source. Human and authority approval remain required for any real operation.
